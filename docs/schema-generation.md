# 模型与建表生成器

`cloudoll gen` 支持原生 MySQL/PostgreSQL。它用于生成模型和新建表，**不是迁移或数据库备份工具**：不复制数据、索引、外键、CHECK、触发器、分区和权限，也不修改已有表。

```sh
# 从 conf.local.yaml 的 postgres 连接生成模型
cloudoll gen -db postgres -c model -t users,orders -p generated_models.py
# 执行可信模型文件，为选中的表生成 DDL
cloudoll gen -db postgres -c table -t users,orders -p generated_models.py
```

## 默认值、安全与类型

- 普通默认值及注释通过原生驱动绑定参数，`0`、`False`、空字符串不会丢失；字符串含引号、反斜杠、百分号和括号都不会被当成 SQL 执行。
- 类型、精度、scale、排序规则来自白名单及数值检查。标识符按数据库方言引用。PostgreSQL 元数据查询绑定表名，使用当前 schema，并且只从主键索引识别主键，不把 UNIQUE 或外键误判为主键。
- 仅时间戳/日期时间列允许有限的 `CURRENT_TIMESTAMP`、`CURRENT_TIMESTAMP(0..6)`、`now()` 默认表达式。其他任意表达式、callable 默认值和计算列明确拒绝，需用户手写 schema。
- PostgreSQL 使用 `GENERATED BY DEFAULT AS IDENTITY`；普通 serial 反向生成时映射为新 identity，不保留原序列名、当前值、步长或共享关系。`GENERATED ALWAYS` 暂不能由 Field 表达，明确报错。
- PostgreSQL 不模拟 MySQL 的 UNSIGNED、字符排序规则、ON UPDATE；出现这些配置时在发出 DDL 前报错。复合主键也会明确拒绝。
- 生成代码采用 `Field[T]`，保留字段类型、空值、精度、注释等元数据；文本用 Python `repr()` 编码，不直接拼进源码。无法安全表示的 Python 字段名会报错，不悄悄改名。类名与 Model/Field 等导入冲突时追加 Record。
- 字符列未指定长度时，varchar 默认 255、char 默认 1。整数显示宽度不生成；它不是数值范围。跨方言转换不承诺位宽完全等价，应审查生成的 DDL。

## 文件与事务边界

生成模型会先完成全部元数据检查和源码语法验证，再追加文件；同名类拒绝重复追加，已有文件不会被覆盖。建表入口只收集当前模块中定义的 Model 子类，跳过导入的模型和无关 Python 类。

模型文件本质上是可执行 Python，**只能加载可信本地文件**。源码转义不意味着可以安全执行第三方模型文件。

建表前检查所有选中模型。PostgreSQL 的 CREATE TABLE 和 COMMENT 放在同一事务中，后续失败可以回滚；MySQL DDL 隐式提交，运行时错误可能留下已创建的表，不能承诺整批原子性。不要在已有业务事务中调用建表工具。

`get_col_sql()` 是单列 SQL 预览；MySQL 含反斜杠的字面量因 SQL mode 不确定而拒绝内联。实际执行应使用 `compile_column()` / `compile_table()` 的 SQL 与参数对，或 CLI 建表入口。

## 验证

```sh
python -m pytest -q tests/test_schema_generation.py
python tests/run_local_databases.py --test-file tests/integration/test_schema.py \
  --python .venv/bin/python --python .venv39/bin/python
```

真实数据库用例覆盖默认值/注释、模型反向生成、再次建表、特殊表名、主键识别，以及 PostgreSQL DDL 批次回滚。MySQL 的 DDL 原子回滚用例明确跳过；AWS 不参与这些测试。

语法依据：[PostgreSQL CREATE TABLE](https://www.postgresql.org/docs/16/sql-createtable.html)、[MySQL 8.4 CREATE TABLE](https://dev.mysql.com/doc/refman/8.4/en/create-table.html)。
